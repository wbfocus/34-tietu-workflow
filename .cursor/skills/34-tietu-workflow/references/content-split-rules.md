# 文案拆卡片规则（分镜表）

目标：把一份文档自动拆成"封面 + 内容页(s) + 结尾页(可选)"的分镜表，不用等用户确认，自己判断。

## 第一步：判断内容形态

| 形态 | 特征 | 默认卡片风格 |
|---|---|---|
| 知识点/清单类 | "N个指标/要点/维度/清单" | 内容卡网格（`design-system.md` 第6节 3:4 版式） |
| 流程/步骤类 | 有明确先后顺序、"第一步...最后一步"、业务流转 | 蛇形流程图卡（`design-system.md` 第6节 流程图卡） |
| 痛点解决方案类 | 先抛问题场景，再给破局方法 | 内容卡网格，首页强化"痛点场景"渲染 |
| 课程/产品介绍类 | 卖点、适合人群、大纲、行动号召 | 内容卡网格，通常带结尾 CTA 页 |

同一份文档可以混用：比如"问题很痛 → 方法是流程" 就前几张用痛点渲染，中间几张切到流程图卡。

## 第二步：定张数

- 从文档里数"自然分组"：几大维度/几个步骤/几条要点，这决定内容页数量。
- 内容页数量 4~7 张最舒服；超过 7 条，先按"大类"聚合（比如 40 个指标聚合成 5~7 个维度页，每页内部再用小网格列出细分指标，不要一个指标一张卡）。
- 步骤类如果节点数 ≤ 8，用单张流程图卡；超过 8 就拆成两张流程图卡（如 1-8 步一张，9-N 步另一张），编号连续。
- 是否要结尾引流/总结页：
  - 文档里出现"后台回复/加微信/系统学习/课程"等转化意图 → 加结尾页。
  - 纯知识分享、无转化意图 → 可以不加结尾页，最后一张内容页收尾即可。

## 第三步：定每页标题与要点

- 封面页：主标题（可以是文档标题，或从内容提炼的更抓人版本）+ 数字冲击（"40个核心指标"里的"40"）+ 分类速览（小图标网格，呼应内容页结构）。
- 内容页：标题用"用户能看懂的说法"而不是内部行话，例如"9个指标看'能不能按时还钱'"比"偿债能力指标清单"更有冲击力。每页页眉用 `当前页 / 总页数`。
- 结尾页：一句总结金句 + 转化话术（延续原文档里出现的具体话术，比如"后台回复XX获取课程大纲"），不要编造联系方式或课程名称之外的新信息——原文档没写清楚的关键信息（比如具体暗号、课程名）宁可用原文措辞，不要自己瞎编一个不存在的暗号。

## 第四步：语气与人设

延续 `HTMLcards` 目录里的"老汪"人设：

- 制造业财务实战派，直接、干货、偶尔自嘲（"人肉干电池"这种说法可以借用同款调性，不要生搬硬套原词）。
- 敢下判断，敢说"新手在修补数据，专家在修建工厂"这类对比句式。
- 忌讳：假客气、无意义的营销黑话堆砌、每句话都加"其实"。

## 第五步：产出分镜表（内部使用，不强制展示给用户）

```text
第1张 | 封面 | 标题：xxx | 数字冲击：xxx | 速览分类：xxx
第2张 | 内容 | 标题：xxx | 要点：xxx / xxx / xxx
...
第N张 | 结尾 | 总结句：xxx | CTA话术：xxx
```

想清楚这张表之后直接进入写 HTML 的步骤，不必等待用户点头，除非用户主动要求先看分镜表再出图。
